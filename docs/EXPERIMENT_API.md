## Core Public Entry Points

### `get_experiment_cases(name)`

File:

- [experiments/benchmark_configs.py](../experiments/benchmark_configs.py)

Purpose:

- returns the registered experiment definitions

Behavior:

- if `name == "all"`
  - returns the entire registry
- else
  - returns `{name: registry[name]}`
- unknown names raise `ValueError`

Current registered experiments:

- `swarm_scaling`
- `stigmergy_ablation`
- `baseline_comparison`
- `robot_failure_test`
- `noise_robustness`
- `collective_intelligence_scaling`
- `rl_algorithm_comparison`

### `run_experiments(args)`

File:

- [train/run_experiments.py](../train/run_experiments.py)

Purpose:

- central experiment runner

Behavior:

1. loads experiment cases from `get_experiment_cases()`
2. loops over cases and trials
3. runs training unless `skip_training=True`
4. runs shared evaluation for every trial
5. aggregates metrics across trials
6. writes `trial_metrics.csv` and `aggregate_metrics.csv`
7. generates plots unless `--no-plots` is used

## Experiment Spec Schema

Each experiment spec has the shape:

```python
{
    "default_trials": int,
    "cases": [
        {
            "case_name": str,
            "train_args": list[str],
            # optional:
            "eval_args": list[str],
            "skip_training": bool,
            "n_agents": int,
            "condition": str,
            "algorithm": str,
            "failed_agents": int,
            "noise_std": float,
        }
    ],
}
```

### Meaning of important case fields

- `case_name`
  - used in output paths and CSV rows
- `train_args`
  - passed into the custom trainer CLI parser
- `eval_args`
  - if omitted, evaluation reuses `train_args`
- `skip_training`
  - used for non-learning baselines such as the rule-based controller
- `n_agents`, `condition`, `algorithm`, `failed_agents`, `noise_std`
  - copied into trial and aggregate CSV outputs

## Metric Pipeline

Base metrics carried through the experiment framework:

- `mean_episode_reward`
- `food_retrieved`
- `exploration_coverage`
- `pheromone_usage`
- `episode_length`
- `swarm_efficiency`

Derived in the experiment layer:

- `efficiency_per_robot`
- `convergence_speed`
- `time_to_first_food`

Important note:

- derived metrics are computed in [train/run_experiments.py](../train/run_experiments.py), not in the trainer

## Minimal Usage Examples

### Run one experiment

```bash
python train/run_experiments.py --experiment collective_intelligence_scaling
```

### Run one experiment with a single trial

```bash
python train/run_experiments.py \
  --experiment rl_algorithm_comparison \
  --trials 1 \
  --total-steps 100 \
  --eval-every 0 \
  --eval-episodes 1
```

### Programmatic use

```python
from train.run_experiments import parse_args, run_experiments

args = parse_args(["--experiment", "collective_intelligence_scaling", "--trials", "1"])
run_experiments(args)
```

## How to Add a New Experiment

1. Add a registry entry in [experiments/benchmark_configs.py](../experiments/benchmark_configs.py)
2. Reuse the existing `train_args` and optional `eval_args` mechanism
3. Reuse shared metadata fields if possible
4. If the default CSV outputs are sufficient, no runner changes are needed
5. If special plots are needed, add a plotting branch in [train/run_experiments.py](../train/run_experiments.py)

## Implementation Notes

- Rule-based experiment cases use `skip_training=True` and still flow through the same evaluator and result CSV schema as learned policies.
- Trial counts come from `--trials` when provided, otherwise from the experiment’s `default_trials`.
- `convergence_speed` is estimated from `episode_metrics.csv` by smoothing reward with a moving average and finding the first sustained window near the final smoothed reward level.
- `time_to_first_food` is estimated from `eval_metrics.csv` as the first evaluation episode with `food_retrieved > 0`, or `len(rows) + 1` if food is never found.
